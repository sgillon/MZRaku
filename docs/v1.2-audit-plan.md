# v1.2.0 audit — fix plan

Derived from `docs/v1.2-audit-findings.md`. Category-(a) findings
(if any) surface at the top as immediate hot-fix items.
Category-(c) findings surface at the bottom for reference.

Seven phases across 65 category-(b) findings. Each phase is
self-contained, buildable + smoke-testable on both machines
before the next starts — the same shape v1.1 Phases 1-7 had.
Sequencing puts low-risk landings and real correctness fixes
first, then extractions that make later structural work
possible, then the large machine-class convergence + MainForm
surgery at the end.

## Immediate hot-fixes (category-a)

None — no category-(a) findings surfaced.

## Fix phases (category-b)

### Phase 1 — Documentation freshening + dead-code sweep

**Effort:** medium (many trivial items, one small)
**Contains:** F-003, F-004, F-005, F-006, F-007, F-008, F-009,
F-010, F-011, F-012, F-013, F-014, F-018, F-028, F-029, F-033,
F-041, F-042, F-043, F-054, F-059, F-067, F-CR-001
**Depends on:** none

The safest possible opener. Two threads land together as one
pass: (i) doc drift — every XML/inline comment that still
references in-flight phases, MZ-700-only status for
now-shared classes (Ppi8255, Pit8253, Sound), Phase-B numeric-pad
scaffolding, TBC empirical-check flags on Mz80aMatrixReference,
Debugger/MemoryViewer phase names, orphaned MonitorReady doc,
Video.cs FG/BG contradiction, MZ700Memory RAM-or-RAM
self-contradiction; (ii) dead code — unused Ppi8255 members
(MotorChanged/IntMaskChanged/CassetteMotorOn/SpeakerGate/
SetCassetteRead), Cassette.DumpBasicWaitCode, Keyboard.SetShift,
MzGlyphCatalog trim, RomKeyTables trim, Pit8253.Counter0FrequencyHz,
Mz700SoundReference.ExpectedEvents, FontSheetForm._machine,
SoundDiagnosticForm.FillMonoLabel, DumpMz80aBasicPointerCandidates
(148 lines from MainForm), the Settings surface cleanup batch,
and the OnLoaded event decision (F-007 — probably wire; possibly
delete). Zero runtime behaviour change expected across the whole
phase apart from the OnLoaded wire (one line of extra status-bar
text on cassette LOAD). Landing this first shrinks the surface
every subsequent phase reads.

### Phase 2 — MZ-80A parity fixes + real correctness patches

**Effort:** medium
**Contains:** F-026, F-031, F-032, F-034, F-038, F-051, F-057,
F-058, F-063, F-CR-002
**Depends on:** Phase 1

Second-safest landing, focused on genuine bugs and asymmetries
users can hit today. F-026 fixes the Ctrl+R matrix-leak on
MZ-80A. F-057 fixes `--mz80a --dump=` NREing at frame 120.
F-058 fixes SwitchMachine losing window geometry. F-031 fixes
Reset-button enablement on MZ-80A character slots (currently
reads MZ-700 CharMap.Defaults). F-032 fixes KeyCaptureControl
labelling on MZ-80A. F-034 unlocks the Keyboard Matrix debug
pane for MZ-80A users. F-038 replaces the shift-slot magic
number with a context property. F-051 makes Settings-Apply's
confirm dialog stop silently omitting MZ-80A keyboard edits.
F-063 + F-CR-002 together remove the always-on trace scaffolding
(`_traceEnabled` public field hardcoded true, Pit.WriteLog +
Mem.BankSwitchLog growing unbounded on every write) — landed
together so the encapsulation fix and the perf fix share a
commit. After Phase 2, both machines behave symmetrically on
the release-check.md walk.

### Phase 3 — Naming + configuration hygiene

**Effort:** small
**Contains:** F-002, F-065, F-068, F-069
**Depends on:** Phase 1

Mechanical fixups that clarify vocabulary before larger
refactors touch these files. F-002 renames `VideoRenderer` →
`Video` for sibling consistency (MZ-80A already has `Mz80aVideo`,
field is `Video` on both machines). F-068 renames `Settings.Type`
→ `Settings.CurrentMachine` to stop shadowing the CLR `Type`
concept. F-065 drops the seven pre-Phase-5.1a legacy-key
fallbacks from Settings.Load (v1.1's auto-migration means any
active user has already migrated). F-069 makes MZRaku.csproj's
ROM copy-to-output condition machine-agnostic. Each is
low-risk and read-once — deferring past this point makes
larger phases carry the stale names.

### Phase 4 — Shared helper extractions

**Effort:** medium
**Contains:** F-035, F-039, F-044, F-045, F-047, F-CR-003,
F-CR-004, F-CR-005
**Depends on:** Phase 1

Small, safe extractions that consolidate duplicated helpers
before the big structural work needs them. F-044 extracts
`DebuggerCommon` + `DebugToolForm` for the two debugger-side
forms (TryParseAddr, SetTextIfChanged, IsIoWindow, hide-on-close,
geometry persist). F-045 extracts `DiagnosticFormBase` for the
two log-shaped diagnostic forms (BuildButtonRow, Copy/Save,
AutoGroup, FillGroup, ShowWithoutActivation). F-035 collapses
MapKind + LightenOrDarken in the two physical-keyboard-layout
adapters. F-039 lifts Mz80a glyph-lookup out of two UI adapters
into a Hardware static (mirrors MZ-700's MzGlyphCatalog).
F-047 caches char-width + pens in MemoryViewer's owner-draw
path (removes 540 allocations/sec on the intended refresh
cadence). F-CR-003 dedupes LoadEmbeddedIcon between MainForm
and AboutForm. F-CR-004 dedupes MakeStorable / MakeRelativeToBase
between Settings and SettingsForm. F-CR-005 deletes the
Math.Clamp shadow. These land as a batch because each has near-
zero risk and none block each other.

### Phase 5 — MZ-80A keyboard first-class parity + Settings surface split

**Effort:** medium-large
**Contains:** F-017, F-036, F-037, F-046, F-050, F-052, F-053
**Depends on:** Phase 2, Phase 4

The concentrated v1.1 carry-forward work. F-017 introduces the
`IMatrixReference` abstraction (or equivalent) so PcKeyIndex,
MatrixCoverage, and KeyboardMapFile can serve both machines.
F-036 adds Mz80aKeyboardLayout.EssentialKeys +
Mz80aMatrixReference.IsKnownUnreachableFromPc + Mz80aGlyphCatalog
(or equivalent), then wires MZ-80A diagram PC-key labels and
red unreachable-essential outlining through the parameterised
PcKeyIndex. F-037 adds .mzkbd v2 file format (machine tag,
back-compat with MZ-700-only v1) and dispatches
export/import per active machine. F-052 lifts
`IsKeyFullyReachable` + `DescribeKeyForGate` out of SettingsForm
into a Hardware-side `KeyboardReachability` helper serving both
machines, so the safety gate fires on MZ-80A too. F-046 widens
IKeyboardMatrix with `Diag` and `PeekMatrixRow`, letting
HidDiagnosticForm drop its Keyboard?/Mz80aKeyboard? split.
F-050 splits SettingsForm.cs (1322 lines → ~600) by moving the
reachability helper to Hardware, moving mzkbd I/O to
KeyboardMapFile, and optionally splitting tab builders into
partials. F-053 collapses the 20-parameter SettingsSnapshot.Build
via `Snapshot.ApplyTo(Settings)`, simplifying the four parallel
apply/load/diff sites. Landed together because F-050's move of
the reachability helper is the natural landing site for F-052's
parameterisation, and F-053's snapshot cleanup pairs with F-051
from Phase 2. Post-phase, MZ-80A is a first-class peer for the
keyboard editor and the .mzkbd share workflow.

### Phase 6 — Parallel machine class convergence (Hardware)

**Effort:** large
**Contains:** F-001, F-015, F-016, F-021, F-022, F-023, F-024,
F-025
**Depends on:** Phase 2 (F-026 pairs with F-025), Phase 5
(overrides + PcKeyIndex abstractions established)

The Hardware-side architectural refactor. F-001 promotes MzfImage
to a top-level type (both machines stop referencing it as
`Cassette.MzfImage`). F-015 + F-021 extract `KeyboardMatrixBase`
carrying the ~350 lines of _rows/_holds/_stagedKeyBits/_pcShift
bookkeeping that Keyboard.cs and Mz80aKeyboard.cs currently
duplicate. F-016 lifts Keyboard.cs's auto-typer (lines 371-521)
into `KeyboardAutoTyper` for its own reading arc. F-022
refactors CharMap.Defaults to derive from Mz700MatrixReference
the way Mz80aCharMap already derives from Mz80aMatrixReference
(canonical-reference-pattern extension to MZ-700 side). F-023
extracts `MatrixOverrides<TPress>` (or shared MatrixOverrideStore)
serving both machines' override layers with one INI
serialisation path. F-024 extracts `SpecialKeyMapBase<TEntry>`
and moves MZ-700's SlotLabels to derivation from
Mz700MatrixReference (matching MZ-80A's shape). F-025 extracts
`CassetteTrapBase` for the shared LOAD-header + LOAD-data
trap pattern; MZ-700 keeps its SAVE-trap surface as MZ-700-only.
This is the biggest single-phase LOC delta of the release
(net -300 to -400 LOC across the seven areas), and each finding
is a clean extraction with zero runtime behaviour change
expected. Smoke-test both machines' keyboard, cassette, and
character-editing paths after landing.

### Phase 7 — Top-level surface convergence (MainForm + IMachine)

**Effort:** large
**Contains:** F-055, F-056, F-060, F-061, F-062
**Depends on:** Phase 6

The MainForm surgery. F-060 introduces `MzMachineBase : IMachine`
carrying the duplicated Paused/Resume/StepInstruction/StepFrame
debugger-control surface. F-061 extends IMachine with Sound,
VideoFrame, and a small CassetteState struct — the surface
MainForm actually consumes uniformly across both machines.
F-056 then collapses ~15 of MainForm's ~28
`_machine != null / _mz80a != null` branches through those new
surfaces. F-055 extracts three cohesive companion classes:
`AutoLoadOrchestrator` (per-machine BASIC + cassette autoload
pipelines from Timer_Tick), `StatusStripController` (four labels
+ decay + tape/mode/pause label management), `DumpTraceRecorder`
(dump path + trace log + DumpState). F-062 collapses Timer_Tick
from ~300 lines to ~30 by delegating both machine's autoload
blocks to AutoLoadOrchestrator. MainForm shrinks from ~1980 to
~800 lines. Zero runtime behaviour change if the extraction is
faithful — but the risk surface is highest here, so this phase
lands last with the release-check.md walk as the gate. Splits
into 5 commits (one per finding) so a bisect can pin any
regression.
